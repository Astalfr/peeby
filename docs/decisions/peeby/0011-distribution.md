# 0011: Distribution through GitHub Actions, a portable zip and an Inno Setup installer

> Archived from peeby (`D:\DEV\peeby`, abandoned, ADR 0007). Numbers and links are peeby's.

- Status: accepted
- Date: 2026-11-01

## Context

Phase 5 has to turn the repo into a build people can download. The user chose:
- an **Inno Setup** installer next to the portable zip (over WiX/MSI, or a zip only);
- **GitHub Releases on `v*` tags**, with every push and pull request still producing the bundle as a workflow artifact (over artifacts only, or a rolling nightly);
- the **same data locations** for the zip and the installer, `%APPDATA%\peeby` and `%LOCALAPPDATA%\peeby` (over a portable mode with data next to the exe);
- **unsigned** builds for now;
- a third-party notice generated by **cargo-about**, plus links to the exact libmpv build and its sources;
- libmpv fetched in CI by the existing hash-pinned script, **cached** by `actions/cache` (over mirroring the archive into a release of our own);
- **v0.1.0** as the first release.

libmpv is GPL and ships next to the exe, so a release must carry the GPL text and point to the corresponding source. The installer must not need admin rights: Peeby is a per-user app and its token already lives in the user's Credential Manager.

## Decision

- `.github/workflows/ci.yml` on `windows-latest`: fmt, clippy, tests, then `scripts/package.ps1`, which builds the release exe and writes `dist/peeby-<version>-windows-x64.zip`, `dist/peeby-<version>-setup.exe` and `SHA256SUMS.txt`. A tag must equal the crate version; a tag with a `-` makes a pre-release. Builds that are not tagged are versioned `<crate>-dev.<sha7>`.
- The installer (`packaging/peeby.iss`) installs per user into `%LOCALAPPDATA%\Programs\Peeby` (an admin can still pick a machine-wide install), adds a Start menu entry and an optional desktop shortcut, and leaves settings, cache and token in place on uninstall. Its `AppId` never changes.
- The bundle holds `peeby.exe`, `libmpv-2.dll`, `LICENSE.txt` (GPLv3), `THIRD-PARTY-NOTICES.html` (cargo-about), `SOURCES.txt` (Peeby tag, shinchiro package, mpv commit, upstream sources) and `CREDITS.txt` (mascot artwork, Lucide).
- Tools that are not crate dependencies: `cargo-about` (installed with `taiki-e/install-action`), Inno Setup 6 (installed with Chocolatey when the runner lacks it), 7-Zip (preinstalled).

## Consequences

- One script builds the same bundle locally and in CI.
- SmartScreen warns about unsigned downloads until there is a certificate. Signing would be a step after `package.ps1`, run only when the secrets exist.
- The CI cache only delays breakage when shinchiro deletes the pinned release: after that, the pin has to be bumped (build-windows.md (peeby's `docs/build-windows.md`)). If that gets annoying, mirror the archive into a release of our own.
- No auto-update: users download new versions from the Releases page. Revisit if releases become frequent.
- A new license in the dependency tree fails the bundle (`cargo about --fail`) until it is reviewed and added to `about.toml`.
